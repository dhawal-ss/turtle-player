## Weaknesses

### [BLOCKER] Shell's entire UI is English-only, while a reachable picker offers 57 languages

- Evidence: 532 Turtle string keys exist only under turtle/ui/.../composeResources/values/ and turtle/bridge/.../values/, with no values-XX sibling anywhere. The picker is drawn via hook #49 at turtle/ui/.../ShellSettingsPage.kt:136 from ContentSettingsRegistration.kt:73-105.
- Why it matters: Shell replaced upstream's Home, Search, Player, Library, Playlist, Album, Artist, Podcast, Settings, every dialog and every menu (HOOKS.md #22-#54). A listener picks their language, upstream's remaining chrome switches, and the whole of Turtle stays English. Upstream shipped 58 locales, so this is a regression the fork introduced.
- Fix sketch: Move all 532 keys into shared/src/commonMain/composeResources/values/strings.xml under a shell_ prefix so Weblate (docs/strings.md:5) picks them up, delete the per-module catalogs, and repoint turtle/ui and turtle/bridge at com.metrolist.shared.generated.resources. If they must stay in turtle/, register a second Weblate component over both catalog roots. Update turtle/AGENTS.md either way.

### [BLOCKER] Android cloud backup carries the listening history and the drive log off-device by default

- Evidence: androidApp/src/main/AndroidManifest.xml:71-73 sets allowBackup="true" with @xml/backup_rules and @xml/data_extraction_rules. Neither excludes turtle.db (TurtleDatabase.android.kt:8, getDatabasePath) nor files/turtle-drive.log (DriveLog.android.kt:29-32).
- Why it matters: turtle/AGENTS.md states 'Listening history stays on device. Anything sent off-device is opt-in and documented.' The whole play-event log, the taste state, and a flight recorder that includes audio device product names (DriveLog.android.kt:140) upload to Google backup with no prompt. It undercuts the on-device privacy claim that is Turtle's main edge.
- Fix sketch: Add exclude entries for database path turtle.db plus its -wal/-shm siblings, and file paths turtle-drive.log and turtle-drive.1.log, to both androidApp/src/main/res/xml/backup_rules.xml and data_extraction_rules.xml (cloud-backup and device-transfer). These are upstream files, so add one HOOKS.md row. If history should survive a phone swap, keep it only in device-transfer and say so in Settings.

### [MINOR] 36 runCatching and broad-catch sites with no CancellationException handling

- Evidence: 15 files contain runCatching or catch (e: Exception/Throwable) and never mention CancellationException. Worst case: turtle/ui/.../ShellHomeRows.kt:22 does runCatching { TurtleBridge.uiPref(...) }.getOrNull() inside scope.launch, then assigns UI state at :24.

### [MINOR] Engine purity is convention only; nothing in the build or CI can enforce it

- Evidence: turtle/engines/build.gradle.kts:18-20 declares a single jvm target; the comment at :16-17 says iOS targets come 'once we build on macOS'. No ktlint, detekt or CI grep checks imports. Line 22 also sets allWarningsAsErrors false.
- Why it matters: The rule in turtle/AGENTS.md is satisfied perfectly today, but only because contributors remembered. With jvm as the only target, java.util, java.text.Normalizer and String.format all compile in commonMain, so the first violation lands silently and the engines stop being portable to iOS, which is the stated reason the rule exists.
- Fix sketch: Add an iosArm64/iosSimulatorArm64 target (or at minimum linuxX64) in turtle/engines/build.gradle.kts so the compiler enforces purity, or add a step to turtle-engines.yml that greps turtle/engines/*/src for '^import (java|javax|android|androidx|com\.metrolist)' and fails on any hit. Also drop allWarningsAsErrors false for new code.
